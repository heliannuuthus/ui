# UI 文档站视觉重设计提案

Status: Proposed

## 背景

当前文档站采用了明显的编辑式视觉语言：超大标题、楷体、编号章节、贯穿页面的规则线和大面积留白。这套表达在窄屏上具有类似杂志的节奏，但在宽屏和超宽屏上会随着视口继续拉伸，导致内容之间失去联系，辅助元素占据过多视觉注意力，也弱化了公共组件库应有的准确、可靠和易操作感。

本提案将文档站的目标视觉方向定义为：**克制、精致、有温度的现代产品界面**。页面应首先服务于检索、理解和试用组件，再通过有限的品牌字体、向日葵和小猫等元素保留辨识度。

## 目标

- 在桌面和超宽屏上保持稳定、紧凑且有关联的内容构图。
- 建立清晰的内容容器、导航层级和阅读宽度规则。
- 让首页、快速开始和组件文档共享一致的产品界面语言。
- 使用连续、克制的动效表达位置和状态变化。
- 将毛玻璃限制在真正悬浮的功能层，避免装饰性堆叠。
- 保留现有路由、内容信息架构和公共组件边界。

## 非目标

- 不重写文档内容或改变现有路由。
- 不在业务页面中复制公共组件实现。
- 不为了文档站的导航效果向公共组件注入路由语义。
- 不将整个页面改成玻璃材质，也不使用大面积装饰性模糊。
- 不通过扩大正文行长来填满超宽屏。
- 不在本阶段直接改变公共字体默认值；字体兼容性需要单独评估。

## 现状诊断

### 超宽屏内容失联

首页和快速开始页的主要区块直接以视口为布局边界，padding 和 gap 会随视口增长，但缺少统一的最大内容宽度。文案与预览、标题与辅助卡片因此被推向两侧，中间形成没有信息价值的空白。

### 编辑式表达过强

大字号标题、章节编号、细线网格和宽阔留白同时出现，使页面接近字体样张或杂志目录。相同结构在多个页面重复后，版式本身比内容更醒目。

### Hero 面积与信息量不匹配

快速开始 Hero 主要传达标题、简介和三条前置条件，却占据了接近半屏的面积。前置条件卡片与标题距离较远，不能形成一个紧凑的任务起点。

### 步骤结构重复

四段接入步骤都使用编号、图标、大标题和较大的垂直间距。重复的章节表达增加了滚动距离，却没有提高步骤之间的辨识度。

### 字体角色混乱

楷体同时承担标题、正文和控件文本，使品牌表达与功能界面缺少层级。公共组件的默认字体应保持中性，品牌字体只应出现在少量经过选择的位置。

### 装饰缺少内容联系

向日葵和小猫可以形成温暖的品牌记忆，但当前小猫有时漂浮在大面积空白中，更像填补版面的装饰。它应与完成、欢迎或下一步等明确时刻关联。

## 设计原则

### 全宽背景与限宽内容分离

背景颜色、网格或轻微光感可以延伸至整个视口；标题、导航、正文和组件预览必须进入统一的居中内容容器。营销页面的主要容器最大宽度建议约为 `1440px`，超出部分只增加外围呼吸空间，不继续拉大元素间距。

### 稳定的内容密度

页面宽度增加时，应优先扩展导航、检索和上下文区域，而不是增加正文行长。普通文档正文保持约 `56rem` 的最大阅读宽度；快速开始正文控制在约 `720–840px`，代码与交互示例最大可扩展到约 `960px`。

### 功能决定材质

毛玻璃用于悬浮 Header 和当前导航胶囊，以表达它们位于内容之上的功能层。普通正文、代码和组件示例使用清晰的实体表面。避免在已经模糊的表面上再次叠加重度 `backdrop-filter`。

### 动效表达空间关系

动效用于回答“当前位置移动到了哪里”，不用于装饰。顶部导航使用连续移动的选中胶囊；其余内容默认保持静止，只提供必要的 hover、focus、press 和复制反馈。

### 品牌表达保持稀缺

品牌字体、向日葵和小猫应成为少量、可识别的签名，而不是全局样式。稀缺使用能让这些元素更有记忆点，也能保持组件示例的中立性。

## 页面方案

### 首页

- Hero 背景保持全宽，内容进入最大约 `1440px` 的居中容器。
- 文案与组件预览在容器内组成两栏，停止随视口无限分离。
- 收紧两栏间距，并让右侧预览靠近页面视觉中心。
- 标题仍可保持品牌表现力，但降低超宽屏上的最大字号和断行侵略性。
- 安装命令与主要行动保持在文案一侧，形成完整的接入路径。
- 装饰轨道或背景光感不得成为填补空白的主要手段。

### 顶部导航

- 首页品牌入口与“快速开始”“设计理念”“组件”共享一个连续的当前位置指示器。
- 首页激活时，胶囊包裹向日葵与 `Heliannuuthus UI`；进入其他页面时，胶囊移动到对应导航项，并同时插值位置与宽度。
- 动画应无弹跳、可中断；快速连续切换时从当前屏幕位置重新定向。
- Header 负责背景模糊，胶囊使用半透明填充、顶部高光细边和轻量阴影形成玻璃感。
- 键盘焦点环独立于选中胶囊，必须立即出现，不能依赖动画表达焦点。
- 该交互由文档站布局层协调，不向公共 `Segmented` 组件传递路由语义。

### 快速开始

- 页面进入研发手册侧栏后，不再渲染独立 Hero、“开始之前”卡片或重复的步骤导航，直接从第一步正文开始。
- 页面标题保留为文档元数据与无障碍标题，不占用可见布局空间。
- 步骤正文采用稳定的单列阅读结构；编号缩小为辅助定位，不再与图标和大面积留白组成重复章节封面。
- 代码面板可以比正文略宽，但仍需遵循约 `960px` 的最大宽度。
- 小猫移动到接入完成或“下一步”区域，作为完成反馈或品牌签名。

### 组件文档

组件文档保留左侧组件导航、中央正文和右侧页内目录的三栏结构，但提高双侧栏在大屏中的占比：

- 研发手册与组件导航统一使用 `clamp(22rem, 25vw, 30rem)`，在容纳清晰分组的同时避免侵占正文区域。
- 右侧页内目录使用 `clamp(18rem, 18vw, 22rem)`。
- 研发手册正文靠近左侧导航起始，不在剩余区域内再次居中，避免导航与内容之间形成无意义断层。
- 普通正文继续保持约 `56rem` 的最大阅读宽度并居中，不消费所有剩余空间。
- 超宽屏增加的是导航、分组、检索和页内上下文空间，而不是正文行长。
- 侧栏内部可适当增加横向 padding、分组间距和当前项的视觉识别度。
- 扩大侧栏适用于研发手册和组件文档；设计理念页仍保持独立布局。

## 响应式行为

| 范围          | 布局行为                                                             |
| ------------- | -------------------------------------------------------------------- |
| 超宽屏        | 使用响应式双侧栏上限和居中内容容器；正文宽度保持稳定。               |
| `1400px` 以上 | 研发手册与组件文档展示左侧导航、中央正文和右侧目录。                 |
| `1400px` 以下 | 隐藏右侧目录；左侧导航回落至 `19rem`。                               |
| `980px` 以下  | 首页与营销页面的双栏内容转为单栏，预览区域居中。                     |
| `860px` 以下  | 左侧组件导航转换为现有抽屉交互；顶部主导航折叠。                     |
| `720px` 以下  | 快速开始的步骤说明转为单列，代码区域保持独立横向滚动。               |
| `320–414px`   | 不出现水平滚动；按钮和导航文字不换成两行；代码区域内部独立横向滚动。 |

断点是行为边界，不是内容宽度的替代品。所有宽屏页面仍应通过最大宽度约束维持构图。

## 字体策略

- 公共组件的功能文本应使用中性的系统无衬线字体栈，并允许消费者通过 Provider 或语义变量覆盖。
- 文档站正文、导航、表单控件和代码说明使用清晰的无衬线字体；代码继续使用等宽字体。
- 楷体仅保留在品牌名称、少量展示标题或明确的品牌时刻，不作为全局 `sans` 字体。
- 公共字体默认值的变化可能影响所有消费者，实施前必须单独检查视觉回归和向后兼容性。

## 材质与动效

### 玻璃层级

1. 页面内容：实体背景，不使用模糊。
2. 粘性 Header：半透明背景与统一的 `backdrop-filter`。
3. 导航胶囊：半透明填充、高光边缘和轻量阴影，不重复施加强模糊。

玻璃效果必须在浅色、深色和复杂背景上保持文字对比度。浏览器不支持背景模糊时，应自然退化为较不透明的实体背景。

### 动效规则

- 选中胶囊使用临界阻尼或等效的无弹跳 spring，感知时长约 `280–360ms`。
- 动画只改变 `transform`、尺寸插值所需的布局测量结果和透明度，避免引发布局抖动。
- 路由切换不得等待胶囊动画结束；动画必须可随新目标中断和重定向。
- `prefers-reduced-motion: reduce` 下取消空间移动，使用不超过 `150ms` 的淡化或直接切换。
- `prefers-reduced-transparency: reduce` 下提高表面不透明度并移除背景模糊。
- `prefers-contrast: more` 下使用更实的背景和清晰边界。

## 实现边界

- 页面结构与路由状态保留在 `apps/docs`。
- 文档站继续通过 `@heliannuuthus/ui` 的公共入口使用基础组件。
- 不创建平行的文档站基础组件库。
- 跨品牌入口与主导航的共享胶囊属于文档站组合行为，可由 Header 布局层统一测量和驱动。
- 不因该动画扩展 `Segmented` 的公共 API，除非后续证明存在领域无关且可复用的需求。
- 公共字体变量的调整必须独立评审、记录兼容性并完成包级验证。

## 建议实施顺序

1. 建立统一内容容器和响应式组件文档双侧栏，先解决超宽屏比例。
2. 调整字体角色和页面字号层级，降低编辑式视觉强度。
3. 重构首页 Hero 与快速开始页面结构。
4. 实现顶部导航的共享滑动胶囊。
5. 调整品牌插图位置，并完成深色模式和无障碍降级。
6. 在目标视口完成视觉回归后再评估公共字体默认值是否发布。

## 验收标准

### 首页

- 在 `1440px`、`1920px` 和更宽视口上，文案与预览保持在同一视觉组内。
- 背景可全宽延伸，但主要内容不超过约 `1440px` 的布局容器。
- 窄屏单栏布局不退化，且没有水平滚动。

### 顶部导航

- 首页和三个一级导航目的地都有清晰的当前状态。
- 胶囊可在品牌入口与导航项之间连续移动，并适应不同标签宽度。
- 快速连续切换不会闪烁、跳回或阻塞导航。
- reduced motion 和 reduced transparency 均有可用降级。

### 快速开始

- 首屏直接显示步骤入口和第一步内容，不重复侧栏已经表达的页面目的。
- 页面不再使用独立 Hero 或前置条件卡片。
- 步骤内容的正文与代码宽度稳定，编号不压过内容标题。
- 小猫与完成或下一步语义关联。

### 组件文档

- 超宽屏下左右侧栏占比明显高于当前固定 `17rem + 14rem` 的布局。
- 正文保持约 `56rem` 的最大宽度，不因侧栏加宽而出现过窄或过长行。
- `1400px` 以下右侧目录隐藏，`860px` 以下左侧栏正常转换为抽屉。
- 侧栏扩大不影响设计理念和首页。

### 视觉与无障碍

- 浅色和深色模式均保持稳定对比度与材质层级。
- 键盘可访问所有导航与步骤，焦点位置始终可见。
- 在 `320px`、`375px`、`414px`、`768px`、`1400px`、`1440px` 和 `1920px` 视口完成检查。
- 不出现两行主导航标签、页面级水平滚动或依赖 hover 才能访问的信息。
