# Layout 布局

{"使用 Header、Content、Footer 和 Sidebar 组合页面骨架，让常见布局关系保持清晰且可嵌套。"}

## 何时使用

- 页面需要稳定的页头、主体和页脚结构。
- 应用需要在内容左侧或右侧加入导航、目录或详情区域。
- 复杂页面需要通过嵌套 Layout 组合纵向与横向区域。

:::note{title="布局职责"}
Layout 只描述区域之间的结构关系；导航状态、路由和业务内容仍由应用负责。
:::

## 布局模式

::::tabs
:::tab{label="纵向组合" value="vertical"}
Header、Content 和 Footer 默认纵向排列，Content 自动占据剩余空间。
:::
:::tab{label="横向组合" value="horizontal"}
Layout 直接包含 Sidebar 时切换为横向排列，嵌套 Layout 可继续组织主体区域。
:::
::::

## 折叠状态模型

| 属性                 | 职责                                                                                                               |
| -------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `collapsible`        | 只决定是否渲染内置折叠触发器；它不是折叠状态。传入节点可替换默认图标。                                             |
| `defaultCollapsed`   | 仅初始化非受控状态。提供 `collapsed` 后会被忽略；在非受控模式下，若初次渲染已低于 `breakpoint`，侧边栏会优先折叠。 |
| `collapsed`          | 受控状态。组件不会自行改写它，父组件需要在 `onChange` 中应用新值。                                                 |
| `onBreakpointChange` | 首次检测以及每次进入或离开断点范围时触发；`below` 表示当前是否低于断点。                                           |
| `onChange`           | 折叠请求真正改变当前状态时触发，并通过 `reason` 区分 `breakpoint` 与 `trigger`。                                   |

## 无障碍

- Header、Content、Footer 和 Sidebar 默认使用 header、main、footer 和 aside 语义元素。
- 同一页面只应保留一个 Content 主地标；局部布局请使用普通内容容器，避免出现多个 main。
- Sidebar 中的导航或详情区域需要提供可辨认的 aria-label。

## 避免事项

- 不要把所有区域平铺在同一个 Layout；跨整页的 Header 和 Footer 应包住中间的嵌套 Layout。
- 文字导航在低于 :hint[布局断点]{title="由 breakpoint 属性指定的响应式阈值"} 时通常不适合压成图标栏。

:::collapse{title="窄屏导航建议"}
将 collapsedWidth 设置为 0，并组合 Drawer 提供完整导航；不要只缩窄文字导航。
:::
