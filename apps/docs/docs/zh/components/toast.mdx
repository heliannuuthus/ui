# Toast 轻提示

{"在页面顶部短暂反馈操作结果；内置 success、info、warning、error 四种语义样式，并可通过 Provider 隔离全局或局部通知通道。"}

## 何时使用

- 操作已经结束，需要短暂确认结果，但不应打断用户当前任务。
- 组件树中的深层操作需要调用统一的页面级通知，或工作区内部需要独立的局部通知。

## API

`Toast`、`Toast.Provider` 与 `Toast.Toaster` 共用以下容器配置。

`defaults` 使用 `ToastDefaults`；单条 `toast(...)`、各语义命令和 `toast.custom(...)` 使用 `ToastOptions`。两者共用 `classes` 槽位，`styles` 仅配置操作与取消按钮。单条按钮的 `action.style`、`cancel.style` 优先于对应的 `styles`。

`toast.promise` 使用 `ToastPromiseOptions<Data>`，保留 loading、success、error、description 与 finally 回调，以及返回值的 `unwrap()`。success 和 error 可返回 ReactNode 或含 `message` 的 `ToastPromiseMessage`，其中的通知配置同样会被适配。`getHistory()` 与 `getToasts()` 保留上游返回模型与字段名称。`id` 和 `toasterId` 保持原路由规则；`useToast()` 返回所在 Provider 通道的命令。

## 无障碍

- Toast 使用非阻塞通知区域；消息标题应简短，并在 description 中说明必要上下文。
- 局部通知的父容器必须可见且尺寸稳定，避免通知被意外裁切到无法阅读。

## 避免事项

- 不要在同一应用根部挂载多个未指定 id 的全局 Provider，否则同一通知可能重复展示。
- scope="local" 时父容器需要 position: relative 和 overflow: hidden。
- 需要用户立即确认的危险操作使用 Alert Dialog，持续存在的页面状态使用 Alert。
