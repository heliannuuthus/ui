# 交互设计 Tips

好的交互让用户知道“现在发生了什么、接下来能做什么、是否已经完成”。组件提供底层能力，产品仍需要为真实任务选择合适的反馈和流程。

## 操作与反馈距离

反馈应靠近触发它的操作。字段错误显示在字段附近；页面保存结果可以使用 Toast；需要用户立即处理的阻断问题使用 Alert 或 Dialog。不要用全局 Toast 代替所有表单错误。

## 加载状态

- 小于约 300ms 的操作通常不需要闪现加载指示器。
- 提交按钮进入 loading 后保留原有宽度，避免布局跳动。
- 页面骨架应模拟真实内容结构，而不是铺满同尺寸灰条。
- 后台刷新尽量保留现有内容，并在局部表达更新状态。

## 弹层选择

| 场景                 | 推荐组件                 |
| -------------------- | ------------------------ |
| 补充信息或轻量操作   | Popover                  |
| 从一组命令中选择     | Dropdown Menu 或 Command |
| 必须完成或取消的任务 | Dialog                   |
| 明确的高风险确认     | Alert Dialog             |
| 窄屏上的多步骤任务   | Drawer                   |

## 动效

动效用来解释位置、层级和状态变化。位移应短而可中断，避免为普通导航添加弹跳。进入和退出需要保持空间关系，并尊重 `prefers-reduced-motion`。毛玻璃只用于需要表达浮层关系的功能表面，同时提供 `prefers-reduced-transparency` 降级。

## 键盘与焦点

- 所有操作必须能通过键盘到达，并保留清晰的 `:focus-visible`。
- Dialog 打开时把焦点送入内容，关闭后还给触发器。
- 菜单使用方向键导航，Tab 用于离开复合控件，而不是遍历每个菜单项。
- 图标按钮必须提供可感知名称；Tooltip 不能是唯一名称来源。

## 危险操作

确认框只用于难以恢复且影响明确的操作。文案应写清对象和后果，例如“删除工作区后，成员将无法访问其中的项目”，而不是只写“确定要继续吗？”。可以撤销的操作优先提供撤销，而不是增加确认步骤。
