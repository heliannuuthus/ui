# CSS 设计与定义

组件代码和样式分别发布。先在应用入口导入一次公共样式，再按需要引入组件。主题切换、方向和组件默认值由 [全局 Provider](/zh/docs/provider) 负责，不放在这一页混讲。

## 引入样式

把公共样式放在应用入口，确保它先于业务样式加载。组件不会在运行时插入 CSS，也不要求业务项目安装 Tailwind 插件。

```tsx title="main.tsx"
import '@heliannuuthus/ui/styles.css';
import './app.css';
```

只导入一次即可。重复导入不会增加能力，反而会让层叠顺序更难判断。

## 样式层级

样式按职责分为四层：基础层处理 reset、字体继承和页面默认值；主题层声明语义变量；组件层使用这些变量；应用样式负责页面布局和品牌差异。

业务项目通常只需要修改语义变量和公开样式入口。不要依赖组件内部的 DOM 层级或生成类名，它们不属于稳定接口。

## 页面颜色

`--background` 是页面底色，`--foreground` 是默认文字颜色。两者决定文档、表单和空白区域的基础对比度，适合在确定整套产品明暗基调时一起调整。

```css title="app.css"
:root {
  --background: oklch(0.99 0.004 260);
  --foreground: oklch(0.2 0.015 260);
}
```

不要用它们表示卡片选中、成功或警告。页面颜色承担的是全局底色，不是业务状态。

## 卡片与浮层

`--card` 和 `--card-foreground` 用于页面内的实体表面，例如 Card。`--popover` 和 `--popover-foreground` 用于菜单、提示和下拉浮层。

```css title="app.css"
:root {
  --card: oklch(1 0 0);
  --card-foreground: var(--foreground);
  --popover: oklch(1 0 0);
  --popover-foreground: var(--foreground);
}
```

卡片可以接近页面背景；浮层需要靠边框或阴影与下方内容分开。两者使用独立变量，是为了允许它们在深色模式中采用不同的明度。

## 操作颜色

`--primary` 表示主要操作，`--secondary` 表示较弱的并列操作，`--accent` 用于悬停或当前项。每个背景色都有对应的 `-foreground` 文字色。

```css title="app.css"
:root {
  --primary: oklch(0.56 0.18 255);
  --primary-foreground: oklch(0.99 0 0);
  --secondary: oklch(0.95 0.01 260);
  --secondary-foreground: oklch(0.25 0.02 260);
  --accent: oklch(0.94 0.025 255);
  --accent-foreground: oklch(0.3 0.08 255);
}
```

不要把三者理解为三档品牌色。它们描述的是操作层级：一个区域通常只有一个主要操作，其余操作应降低视觉重量。

## 边框、输入框与焦点

`--border` 控制普通分隔线，`--input` 控制输入控件边界，`--ring` 控制键盘焦点环。拆开后可以让输入框比普通分隔线更清楚，同时保留明显的焦点状态。

```css title="app.css"
:root {
  --border: oklch(0.9 0.01 260);
  --input: oklch(0.82 0.015 260);
  --ring: oklch(0.62 0.16 255);
}
```

`--ring` 不是装饰色。修改时要同时检查浅色、深色背景和键盘操作，不能只看鼠标状态。

## 状态颜色

`--success`、`--warning`、`--info` 和 `--destructive` 表示结果或风险。它们应由状态语义决定，而不是由页面配色决定。

```css title="app.css"
:root {
  --success: oklch(0.58 0.14 152);
  --warning: oklch(0.72 0.15 78);
  --info: oklch(0.61 0.14 245);
  --destructive: oklch(0.58 0.2 27);
}
```

颜色不能独自承担信息。错误、警告和成功反馈仍要有文字、图标或可读标签。

## 圆角

`--radius` 是组件圆角的基准值。按钮、输入框、卡片和浮层会从它推导各自的尺寸，而不是全部使用同一个半径。

```css title="app.css"
:root {
  --radius: 0.75rem;
}
```

调整基准值会影响整套组件。页面里偶发的特殊形状应使用局部样式，不要为了一个组件修改全局圆角。

## 覆盖组件样式

简单组件使用 `className` 和 `style` 调整根节点。组合组件通过公开的 `classNames`、`styles` 或子组件属性调整语义槽位。优先改变量，其次使用这些公开入口。

订单、权限、审核结果等业务状态不应写进 UI 主题。它们属于业务层，可在页面中选择合适的状态组件和语义颜色。

## 排查覆盖问题

组件完全没有样式时，先检查入口是否导入 `@heliannuuthus/ui/styles.css`。局部覆盖不生效时，检查业务样式是否在公共样式之后加载、变量是否写在组件可继承的祖先上，以及深色模式是否覆盖了同名变量。

如果只能通过不断提高选择器权重才能生效，通常说明覆盖位置不对，或正在依赖组件的内部结构。
