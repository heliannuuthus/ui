# Layout

{"Use Header, Content, Footer, and Sidebar to combine page skeletons to keep common layout relationships clear and nestable."}

## When to use

- Pages need a stable header, body, and footer structure.
- Apps need to include navigation, table of contents, or details areas to the left or right of the content.
- Complex pages require combining vertical and horizontal areas through nested layouts.

:::note{title="Layout responsibility"}
Layout describes structural relationships between regions; navigation state, routing, and product content remain application concerns.
:::

## Layout patterns

::::tabs
:::tab{label="Vertical composition" value="vertical"}
Header, Content, and Footer are arranged vertically by default, with Content filling the remaining space.
:::
:::tab{label="Horizontal composition" value="horizontal"}
Layout switches to a horizontal arrangement when it directly contains Sidebar; a nested Layout can continue organizing the main region.
:::
::::

## Collapse state model

| Property             | Responsibility                                                                                                                                                                       |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `collapsible`        | Only controls whether the built-in trigger renders; it is not the collapsed state. Pass a node to replace the default icon.                                                          |
| `defaultCollapsed`   | Only initializes uncontrolled state. It is ignored when `collapsed` is provided; in uncontrolled mode, an initially matched `breakpoint` takes precedence and collapses the sidebar. |
| `collapsed`          | The controlled state. The component does not mutate it; the parent must apply the next value from `onChange`.                                                                        |
| `onBreakpointChange` | Fires after the first breakpoint check and whenever the viewport enters or leaves the range; `below` reports whether it is currently below the breakpoint.                           |
| `onChange`           | Fires when a collapse request actually differs from the current state and identifies `breakpoint` or `trigger` as its `reason`.                                                      |

## Accessibility

- Header, Content, Footer and Sidebar use header, main, footer and aside semantic elements by default.
- Only one Content main landmark should be retained on the same page; please use ordinary content containers for local layout to avoid multiple mains.
- Navigation or detail areas in sidebars need to provide a recognizable aria-label.

## Avoid

- Do not tile all areas in the same Layout; the Header and Footer that span the entire page should wrap the nested Layout in the middle.
- Text navigation should not be compressed into an icon rail below the :hint[layout breakpoint]{title="The responsive threshold selected by the breakpoint property"}.

:::collapse{title="Narrow navigation guidance"}
Set collapsedWidth to 0 and compose Drawer for complete navigation instead of merely narrowing text navigation.
:::
